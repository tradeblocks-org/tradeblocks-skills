# From a description to the author settings

Use this when there is no author backtest, only a description of the strategy: the user's own file (e.g. `description.md`), typed text, a post, or a transcript (text from a link). You write the author run's Option Omega settings yourself. Whether that translation is faithful is checked by the rule sheet and C1, not here.

1. **Load the `run_backtest` input schema first.** Write the settings as exactly the value of its `parameters`: flat, no wrapper, only fields the schema knows. Save them as `<run folder>/source.settings.json` (not `author.settings.json`, which the run request writes) and pass that file as `--settings` in step 3.
2. **One value per core field.** A core field (`thresholds.json` C1 `coreFields`) needs one value from the source. A range or vague phrase is missing ("$1.00 to $1.75", "usually 50 to 60", "30 to 60 minutes apart", "late morning", a count without times ("six entries a day")): write no value, mark the field `assumed` with the source's words as `quote`. Never pick a usual value, a midpoint or a plausible choice. A single value is stated ("about $1.50", "every 45 minutes from 11:00", "each day" (every trading day) for `days_traded`). `useExactDte`: `true` for 0 DTE or an exact DTE the source states, else `false`; the run request refuses it unset. A month-only date is stated: `rangeStart` is the 1st of the month, `rangeEnd` its last day (Option Omega skips non-trading days). Mark a stated field with a `quote` copied literally from the source; the script checks it. Set `source.built_from` to `"description"`.
3. **Stops.** An Option Omega `Percentage` stop is the loss in % of the premium: a 1x loss is `maxLoss` 100 with `lossType` `Percentage`. Loss wording names the loss: "loss of 2x the credit", "when the loss reaches 2x the credit", "loses 2x the credit", "lost 2x the credit" → `maxLoss` 200. Credit or price wording names the spread's price: "stop at 2x the credit received", "when the spread reaches 2x" → a 1x loss, `maxLoss` 100 ("stop at 3x credit" → 200); "stop loss" or "stoploss" is loss wording: "stop loss at 2x the credit received" → 200. A bare "2x stop" without loss, credit or price wording is not stated (`stop` `assumed`). The run request checks a stated quote with one multiple against `maxLoss`. State the stop mode (`intra-minute` or `minute`) only when the source says it. Otherwise mark `stop_mode` `assumed`; the run request then uses intra-minute stops.
4. **Defaults.** Only the default fields (`secondaryFields`) get a default when the source does not state them: no entry filter, no re-entry, 1 contract per entry (`maxContractsPerTrade` 1, `allocationPercentage` 0, `ignoreMarginRequirements` true; Option Omega refuses allocation 0 with margin on); mark it `assumed` in the rule sheet. Starting funds: write the source's amount only when the `sizing` quote names it; otherwise the run request uses $500,000, marked assumed. Never invent a filter or an exit that the source does not name.
5. **Strike sign.** A child leg's `parentStrikeOffset` is its strike minus the parent's. For a credit spread the long leg is further out of the money: put long leg = −width, call long leg = +width. A stated credit per spread is `SpreadPremium` on the short leg (`spreadPremium` = that credit): Option Omega targets the whole spread's net credit with it, not the short leg's own price. A put long leg at +width builds a debit spread; the run request refuses it (`INVERTED_SPREAD`) when the rule sheet's `structure` names a credit spread or an iron condor.
6. **Costs.** Write the source's slippage and fees only when it states them; otherwise leave the cost fields out. Unknown costs never match the user's base costs, so the run request adds `author_base` (the realistic run) at those costs.

With every core field stated, the author run is built from this file like any other run (step 3) and saved under its label.
